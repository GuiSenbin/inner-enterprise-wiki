## 1. 总体设计
[[组合风控预警平台]]采用“前端工作台 + 后端接口 + 数据存储 + 日志审计”的轻量架构。技术选型包括[[Python]]、[[Kafka]]、[[PostgreSQL]]、[[Redis]]、[[Prometheus]]，优先满足可维护、易部署和便于[[监控运维]]的要求。

## 2. 技术组件
| 组件 | 用途 | 责任部门 |
| --- | --- | --- |
| [[Python]] | 数据处理、批任务和智能问答服务编排。 | [[信息技术部]] |
| [[Kafka]] | 交易、估值、风控等事件流转。 | [[信息技术部]] |
| [[PostgreSQL]] | 业务数据、配置数据和审计记录存储。 | [[信息技术部]] |
| [[Redis]] | 会话、热点指标和短周期计算结果缓存。 | [[信息技术部]] |
| [[Prometheus]] | 服务指标采集和运行状态监控。 | [[信息技术部]] |

## 3. 数据流
1. 业务人员在内部业务工作台提交或查询数据。
2. 后端服务由[[Python]]承载，完成[[身份认证]]、[[权限管理]]和业务规则校验。
3. 业务数据写入[[PostgreSQL]]，热点数据写入[[Redis]]。
4. 关键事件进入[[审计日志]]，运行指标由[[Prometheus]]采集。

## 4. 安全与接口
系统接口遵循[[接口设计]]规范，所有内部调用需要携带用户身份信息。涉及敏感字段时执行[[数据脱敏]]，涉及审批事项时进入[[审批流]]。
